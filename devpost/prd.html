StoryWorld Architect

Product Requirements Document (PRD): User Journey, 5-Domain Schema, What-If Simulation Engine, and Measurable Acceptance Criteria.

🗺️ End-to-End User Journey (60–90s Demo Flow)

How the creator moves from an initial premise to an interactive counterfactual consequence cascade:

📑 PRD Technical & Product Specifications

🌍 1. World Overview

  • name: Name of the fictional world
  • premise_summary: 2–3 sentence foundational description
  • core_conflict: Primary systemic or geopolitical struggle
  • defining_theme: Thematic anchor (e.g. solar energy vs. shadows)

👤 2. Characters (3–4)

  • id: Unique ID (e.g., char_1)
  • name: Character name and title
  • role: Narrative role/profession
  • motivation: Core desire or personal mission
  • faction_allegiance: Reference to world faction
  • connection_to_rule: How they rely on/defy a world rule

⚔️ 3. Factions (2–3)

  • id: Unique ID (e.g., fac_1)
  • name: Faction name
  • agenda: Strategic or ideological goal
  • power_source: How they maintain influence or force
  • rivalry: Opposing faction or adversary
  • territory: Primary seat of power

🏰 4. Locations (2–3)

  • id: Unique ID (e.g., loc_1)
  • name: Location title
  • environment: Terrain and atmospheric feel
  • strategic_value: Why factions contest this region
  • connection_to_rule: Physical manifestation of world laws

⚖️ 5. World Rules (3–4)

  • id: Unique ID (e.g., rule_1)
  • name: Short title (e.g., "Solar Magic Dependency")
  • rule_statement: Exact physical/mystical law
  • systemic_importance: What collapses if this law is altered

⚡ Structured Consequence Schema (Causal Linkage)

Every simulation produces an interconnected consequence packet that explicitly explains why the world mutated:

  • counterfactual_rule: The altered rule statement as modified in What-If Lab.
  • macro_shift_summary: 2-sentence macro analysis of the shifting balance of power.
  • character_impacts: Array of affected characters with explicit causal_reasoning ("Because magic works in darkness, they no longer need daylight guards...").
  • faction_impacts: Array of affected factions with power_shift badge and explicit causal_reasoning.
  • location_impacts: Array of affected locations with status_change and explicit causal_reasoning.
1

Arrival & Premise Entry

Creator arrives at the studio, sees the inspiring premise bar, and picks a quick-start preset or enters a custom prompt.

2

Structured World Generation

AI generates 5 interconnected domains with characters referencing factions and locations referencing rules.

3

World Inspection

Creator explores the generated world cards, gaining complete understanding of its fragile systemic balance.

4

Selecting a Rule in What-If Lab

Creator chooses one rule to challenge; the original rule statement is locked into baseline view.

5

Editing the Rule

Creator types an imaginative counterfactual rule (e.g. night magic drains memories).

6

Simulating Consequences

AI counterfactual engine analyzes the mutation against baseline entities and generates a causal cascade.

7

Side-by-Side Comparison & Discovery

Creator reads the side-by-side comparison, reviewing narrative explanations for how characters, factions, and locations responded.

8

Reset or Re-simulate

Creator clicks "Reset to Baseline" to instantly revert, or tries another rule modification.

State 1: Empty / Arrival

Premise hero open; preset world chips ready; workspace in clean standby preview.

State 2: World Generating

Input disabled; animated pulse and status message indicating world synthesis.

State 3: World Active (Baseline)

5 domains fully rendered; entity tags clickable; What-If Lab ready for rule selection.

State 4: Simulating Consequences

What-If Lab inputs locked; progress spinner indicating causal propagation.

State 5: Comparison Active

Side-by-side view showing original vs. modified rule, with consequence cards and reset button.

State 6: Honest Error Banner

Transparent banner explaining API or connection errors, with a clean "Retry" action.

✓
Interconnected World Entities:
